# Phase 2.16: CSV取込・独立車両

基準日: 2026-10-06。現在の実装と未実装計画を区別する。

## 現行のCSV取込

- 保有CSVでメーカー・品番に対応する製品を検索する。
- 製品が見つかればproductIdを設定し、見つからなければIndependentVehicleを作成する。
- 独立車両にはメーカー・品番・名称等を保存する。
- 結果には成功・失敗と製品リンク・独立車両の内訳を表示する。
- クライアントはCSVをチャンク送信し、保有APIは50件単位でトランザクション登録する。
- 製品CSVもPrismaを使い、製品・実車情報を行単位のトランザクションで登録する。
- 既存およびファイル内の管理ID重複を行エラーにし、曖昧な製品照合は自動リンクしない。

CSV列の実際の読取規則は [csv-parser.ts](../src/lib/csv-parser.ts)、DB構造は [schema.prisma](../prisma/schema.prisma) を参照。
isIndependentカラムはなく、独立車両の関連で判定する。

## 独立車両からの製品作成

保有詳細の「この情報で製品を作成」から、独立車両情報を初期値として製品作成フォームを開く。

製品作成フォームは独立車両IDを送り、製品と保有車両の紐付けを同一トランザクションで保存する。
保有更新で製品へ切り替えた場合はIndependentVehicleを削除する。履歴として必ず保持する仕様ではない。

関連更新と通常登録・CSVの共通化は [リファクタリング計画R2](../../docs/refactoring-plan.md) で完了済み。

## 独立車両の一括製品変換（Phase 2.16.3）

保有車両一覧で独立車両を複数選択し「製品に変換」を実行する（`POST /api/owned-vehicles/convert-to-products`、最大200両、本人の保有車両のみ）。

- メーカー+品番（大文字小文字無視）が同じ独立車両を1つのグループにする。
- グループごとに、同じメーカー・品番の製品が無ければSINGLE製品を新規作成（名称・説明・車種は先頭の車両から）、1件あればその製品へ紐付ける。
- 紐付けた独立車両情報は削除する。グループ単位でトランザクションを分け、失敗したグループは他に影響しない。
- メーカーまたは品番が未設定、独立車両でない、既存製品が複数ある場合はスキップして理由を返す。
- 実装は `convertIndependentVehiclesToProducts`（`src/lib/server/products.ts`）。
- バリエーション（同一品番の別製品）の扱いはR0の照合方針が未決のため、既存製品が複数ある場合は自動で選ばない。
