# Phase 2.16: CSV取込・独立車両

基準日: 2026-10-05。現在の実装と未実装計画を区別する。

## 現行のCSV取込

- 保有CSVでメーカー・品番に対応する製品を検索する。
- 製品が見つかればproductIdを設定し、見つからなければIndependentVehicleを作成する。
- 独立車両にはメーカー・品番・名称等を保存する。
- 結果には成功・失敗と製品リンク・独立車両の内訳を表示する。
- クライアントはCSVをチャンク送信し、保有APIはPrismaでバッチ登録する。
- 製品CSV取込は別APIで、Supabaseクライアントを使用する。

CSV列の実際の読取規則は [csv-parser.ts](../apps/web-next/src/lib/csv-parser.ts)、DB構造は [schema.prisma](../apps/web-next/prisma/schema.prisma) を参照。
isIndependentカラムはなく、独立車両の関連で判定する。

## 独立車両からの製品作成

保有詳細の「この情報で製品を作成」から、独立車両情報を初期値として製品作成フォームを開く。

現行画面は製品作成後の保有更新にPATCHを送るが、保有APIはPUTのみのため、自動紐付けは未完了。
保有更新APIで製品へ切り替えた場合はIndependentVehicleを削除する。履歴として必ず保持する仕様ではない。

メソッドの統一、関連更新のトランザクション、通常登録とCSVの共通化は [リファクタリング計画R2](refactoring-plan.md) で管理する。

## 未実装の計画（Phase 2.16.3）

選択した独立車両から製品を一括作成し、対応する保有車両へ紐付ける。
同じメーカー・品番をまとめる規則は、バリエーションを含むR0の照合方針が決まってから確定する。

進捗は [開発状況](development-log.md) を参照。
